# Hook Library

Hooks are compression tools for judge understanding.

## Rule

If the hook is weak, the UI will need to work harder.

## Hook Format 1 — Visible Problem

Every [action] exposes [sensitive thing].
[Project] fixes this by proving [rule] without revealing [data].

## Hook Format 2 — Do X Without Y

Do [valuable action] without [unacceptable exposure].

Examples:

- Settle invoices without exposing invoice data.
- Prove eligibility without revealing identity.
- Pay privately without breaking compliance.
- Verify reserves without exposing customer balances.
- Share proof without leaking the exploit.
- Run feedback analysis without uploading customer comments.

## Hook Format 3 — Pass/Fail

If the proof is valid, [action happens].
If it is changed, expired, replayed, or invalid, [action is blocked].

## Hook Format 4 — Judge Memory Sentence

[Project] is the [simple category] that [memorable proof/action].

Examples:

- Ballast is the bank that proves it.
- Nullis is policy-as-code for Stellar finance.
- BatchGuard is the invoice settlement gate that proves compliance without revealing invoices.
- EdgeVoC is the offline feedback analyst that turns private comments into local insights.
- TrustCheck is the agent verification gate that tests before delegation.
